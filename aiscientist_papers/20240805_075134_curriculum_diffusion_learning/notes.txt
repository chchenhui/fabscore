## Run 3: Cosine Beta Schedule

Description: This run implemented a cosine beta schedule for the noise scheduler, as proposed in the previous experiment plan. The cosine schedule is designed to provide a smoother transition between noise levels, potentially leading to better sample quality and training stability.

Experiment description: Modify the NoiseScheduler class to include a cosine beta schedule option. Train models using this new schedule on all datasets and compare the results with previous runs.

Observations:
1. Training times were consistent with previous runs, ranging from 41.14 to 41.90 seconds across all datasets.
2. Eval losses were generally lower compared to the quadratic curriculum approach (Run 2) and more in line with the baseline (Run 0) and linear curriculum (Run 1) results.
3. KL divergence values were significantly higher across all datasets compared to previous runs:
   - Circle: 12.42 (vs 0.36-0.50 in previous runs)

The cosine beta schedule appears to have had a substantial negative impact on sample quality, as indicated by the much higher KL divergence values. This is unexpected, as cosine schedules are often reported to improve performance in diffusion models. 

These results suggest that the cosine beta schedule, at least in its current implementation, may not be suitable for these low-dimensional datasets or may require further tuning. The significant increase in KL divergence across all datasets indicates that the generated samples are much less similar to the true data distribution compared to previous approaches.

Further investigation is needed to understand why the cosine schedule performed poorly. Possible areas to explore include:
1. Verifying the implementation of the cosine schedule
2. Adjusting the parameters of the cosine schedule
3. Analyzing the noise levels at different timesteps to ensure they behave as expected
4. Examining the sample quality throughout the diffusion process to identify where the quality degradation occurs

Given these unexpected results, it may be beneficial to revisit the baseline approach and focus on other aspects of the model architecture or training process that could potentially improve performance.

Description: This run investigated the impact of increasing the model capacity by doubling the hidden size (from 256 to 512) and the number of hidden layers (from 3 to 6) in the MLPDenoiser.

Experiment description: Modify the MLPDenoiser class to increase the hidden size and number of hidden layers. Train models using this larger architecture on all datasets and compare the results with previous runs.

Observations:
1. Training times increased by about 20-25% compared to previous runs, ranging from 50.48 to 51.99 seconds across all datasets. This is expected due to the increased model size.
2. Inference times approximately doubled, increasing from ~0.16-0.17 seconds in previous runs to ~0.34 seconds across all datasets. This is also expected due to the larger model size.
3. Eval losses were generally lower compared to the cosine beta schedule approach (Run 3) and more in line with the baseline (Run 0) and linear curriculum (Run 1) results.
4. KL divergence values were significantly lower than in Run 3 but still higher than in Runs 0-2:
   - Circle: 9.40 (vs 12.42 in Run 3, 0.36-0.50 in Runs 0-2)
   - Dino: 13.27 (vs 15.15 in Run 3, 0.36-1.06 in Runs 0-2)
   - Line: 14.34 (vs 9.45 in Run 3, 0.14-0.16 in Runs 0-2)
   - Moons: 7.28 (vs 11.53 in Run 3, 0.09-0.17 in Runs 0-2)

The increased model capacity appears to have partially mitigated the negative impact of the cosine beta schedule observed in Run 3. While the KL divergence values are still higher than in the initial runs, they show a significant improvement compared to Run 3. This suggests that the larger model is better able to capture the complexities introduced by the cosine beta schedule.

Notably, the 'line' dataset showed worse performance in terms of KL divergence compared to Run 3, while all other datasets improved. This could indicate that the increased model capacity may have led to overfitting on this simpler dataset.

These results suggest that increasing model capacity can help improve performance when using more complex noise schedules like the cosine beta schedule. However, the performance is still not on par with the simpler linear and quadratic approaches used in earlier runs.

Further investigation could focus on:
1. Fine-tuning the cosine beta schedule parameters
2. Exploring different model architectures that might be better suited for these low-dimensional datasets
3. Investigating the impact of regularization techniques to prevent potential overfitting
4. Analyzing the generated samples visually to better understand the nature of the improvements and remaining issues

# Plot Descriptions

1. Training Loss Across Datasets (train_loss.png):
This plot shows the training loss over time for each dataset (circle, dino, line, and moons) across all runs. The figure is divided into four subplots, one for each dataset. Each subplot displays the smoothed training loss curves for all runs, allowing for easy comparison of convergence rates and final loss values. The x-axis represents the training steps, while the y-axis shows the loss value. Different colors are used to distinguish between runs, with a legend provided for easy identification. This plot is crucial for understanding how different approaches (baseline, curriculum learning, cosine beta schedule, and increased model capacity) affect the training dynamics for each dataset.

2. KL Divergence Comparison (kl_divergence_comparison.png):
This bar plot compares the final KL divergence values for each run across all datasets. The x-axis shows the four datasets, while the y-axis represents the KL divergence value. Each run is represented by a group of bars, with different colors for easy distinction. The actual KL divergence values are displayed on top of each bar for precise comparison. This plot provides a clear overview of how well each approach performs in terms of generating samples that match the true data distribution. Lower KL divergence values indicate better performance. This visualization is particularly useful for identifying which approaches work best for specific datasets and for observing overall trends across runs.

3. Sample Quality During Training (sample_quality_during_training.png):
This plot illustrates how the sample quality, measured by KL divergence, evolves during the training process for each dataset and run. Similar to the training loss plot, it consists of four subplots, one for each dataset. The x-axis represents the training steps, while the y-axis shows the KL divergence. Each run is represented by a different colored line. This plot is invaluable for understanding how quickly each approach improves sample quality and whether there are any fluctuations or plateaus during training. It can reveal whether certain approaches lead to faster improvements in sample quality or if they maintain better quality throughout the training process.

4. Generated Samples Across Datasets and Runs (generated_samples.png):
This figure provides a visual representation of the actual samples generated by each run for all datasets. It consists of a grid of scatter plots, where each row represents a different run, and each column represents a dataset. Each scatter plot shows the distribution of generated samples in 2D space, with the x and y axes corresponding to the two dimensions of the data. The color of the points in each plot matches the color used for that run in other plots for consistency. This visualization is crucial for qualitative assessment of the generated samples. It allows for direct comparison between the true data distribution (which should be familiar for these standard 2D datasets) and the generated samples. This can reveal issues such as mode collapse, failure to capture certain features of the distribution, or generation of samples outside the expected range.

These plots, when analyzed together, provide a comprehensive view of the performance of different approaches in training diffusion models on low-dimensional datasets. They allow for both quantitative (through loss and KL divergence metrics) and qualitative (through visual inspection of generated samples) evaluation of the models' performance across different datasets and experimental conditions.
