The `create_results_summary()` function writes `EVAL_CONFIG["num_test_examples"]` directly into `results.md`, so if code had been run with this config, it would have written "100" not "212". This proves `results.md` was NOT generated by running the code with the current config.
2. **LLM mismatch:** `config.py` uses `claude-3.7-sonnet` (Anthropic), but Section 4.4 of the paper states GPT-4 was used.
3. **No intermediate result files:** No `*_results.json` files exist in `claude_code/outputs/` or anywhere in the repo, despite `run_experiment.py` being designed to generate them.
4. **Precision inconsistency:** The claimed precision of 0.8524 is mathematically inconsistent with the claimed confusion matrix (TP=55, FP=10 → precision=55/65=0.8462≠0.8524), indicating independently fabricated numbers.
5. **No ablation code:** The word "ablation" does not appear in any code file; no ablation scripts or configurations exist.
